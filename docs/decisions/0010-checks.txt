Решение 10. Проверки качества

Статус. Принято по умолчанию, как стандартный набор рядом с Vite. Можно заменить.
Дата записи. 2026-11-17.

Контекст
Команда учебная, времени мало. Нужны проверки, которые находят ошибки дёшево, и не нужны те, которые съедят время.

Варианты
1. Vitest для логики, проверка типов при сборке, линтер, ручная проверка на телефонах.
2. Jest. То же самое, но настройки сложнее, чем у Vitest рядом с Vite.
3. Playwright или другие тесты, которые сами кликают по интерфейсу. Надёжно, но дорого по времени.

Выбор
1. Vitest для логики без интерфейса: построение времени с точностью, порядок записей, правила слияния при синхронизации.
2. Проверка типов TypeScript при каждой сборке.
3. Линтер oxlint, он идёт в шаблоне Vite.
4. Форматирование Prettier, один стиль кода для всех.
5. Одна команда npm run check запускает линтер, проверку формата, тесты и проверку типов. Если что-то не так, она заканчивается ошибкой.
6. Ручная проверка на реальных телефонах: установка, работа без интернета, уведомления, вход через Google.

Причины
Ошибки чаще всего прячутся в логике времени и слияния данных, её проще всего проверять небольшими тестами. Интерфейс проверяем руками, он меняется чаще всего.

Последствия
1. Автоматических проверок интерфейса нет.
2. Если останется время, добавится один сквозной сценарий: записать, перезапустить, увидеть запись.
