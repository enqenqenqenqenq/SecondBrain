Решение 4. Синхронизация между устройствами

Статус. Принято.
Дата записи. 2026-11-17.

Контекст
Данные должны быть одинаковыми на телефоне и на компьютере. Сервера у проекта нет, платить за него нечем, и мы хотим, чтобы контроль над данными оставался у пользователя.

Варианты
1. Собственный сервер. Нужны деньги и поддержка, а данные пользователей оказались бы у нас.
2. Облачная база (Firebase и подобные). Привязка к стороннему сервису и данные в чужой базе.
3. Личный Google Диск пользователя, скрытая папка приложения.
4. Прямая связь телефона и компьютера по QR-коду. Нужны оба устройства в сети одновременно.
5. Обмен файлом вручную.

Выбор
Основной путь: личный Google Диск пользователя, доступ только к скрытой папке приложения (drive.appdata). Дополнительно, если успеем: прямая связь по QR-коду, подключение своего сервера, обмен файлом. Режим «только локально» работает на одном устройстве полностью.
Передаётся не вся база, а журнал изменений.

Причины
1. Не нужен свой сервер.
2. Приложение видит только свою папку, остальной Диск ему недоступен. Для Google этот доступ считается нечувствительным.
3. Хранилища подключаются через общий набор из трёх действий (положить, получить, показать список файлов), поэтому другие хранилища можно добавить позже без переделки.

Что проверено
На мини-приложении: вход через Google, запись файла в скрытую папку, чтение, обновление, список файлов, получение нового токена без окна, пока сессия Google открыта.

Последствия
1. Токен доступа живёт один час. Приложение должно запрашивать его заново и, если не вышло, откладывать отправку, а не терять изменения.
2. Пока приложение в режиме «Тестирование», входить могут только добавленные тестовые пользователи, и при входе показывается предупреждение, что приложение не проверено.
3. Не проверено тихое обновление токена после его истечения и после закрытия браузера.
4. Для установочного файла Android понадобится отдельный путь входа, см. решение 2.
5. Одновременные правки на двух устройствах дают конфликт, пользователь выбирает версию. Правила в описании модели данных.
